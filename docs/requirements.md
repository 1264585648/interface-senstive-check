# Interface Sensitive Check — MVP 需求文档

## 1. 产品目标

开发一个纯浏览器插件，用于在用户正常访问网页时，采集当前页面产生的接口响应，并根据预设规则检查返回内容中是否存在明文敏感信息。

MVP 只解决一个问题：

> **接口响应中是否出现了不允许明文返回的敏感数据。**

不判断业务上下文、不判断“是否本人数据”、不做漏洞评级。只要命中启用中的合规规则，即记录为违规项。

---

## 2. MVP 范围

MVP 仅包含以下四个核心能力：

1. 维护敏感信息规则列表
2. 开始采集当前页面接口响应
3. 结束采集
4. 展示采集到的敏感信息

以下功能暂不进入 MVP：

- 风险评分
- 漏洞定级
- 用户身份判断
- 业务上下文推断
- 自动判断数据是否属于当前用户
- 云端上传
- 多用户协作
- 报告中心
- 复杂统计看板

---

## 3. 使用流程

```text
打开目标网页
   ↓
打开浏览器插件
   ↓
确认启用的规则
   ↓
点击「开始采集」
   ↓
正常操作网页
   ↓
插件监听当前 Tab 的 Fetch / XHR 响应
   ↓
响应内容进入本地规则引擎
   ↓
命中规则则记录敏感信息
   ↓
点击「结束采集」
   ↓
查看本次采集结果
```

---

## 4. 页面结构

整体采用简单的双栏布局。

### 左侧：规则列表 + 采集控制

#### 4.1 规则列表

每条规则显示：

- 是否启用
- 规则名称
- 规则说明
- 匹配方式/表达式
- 编辑
- 删除

示例：

| 启用 | 规则名称 | 说明 |
| --- | --- | --- |
| ✓ | 手机号 | 中国大陆完整手机号 |
| ✓ | 身份证号 | 中国居民身份证号 |
| ✓ | 完整出生日期 | 完整年月日 |

MVP 内置规则允许启用/停用。

新增/编辑自定义规则可作为下一阶段能力；代码结构需要预留扩展能力。

#### 4.2 采集控制

只保留两个主要操作：

- **开始采集**
- **结束采集**

状态：

- 未采集
- 采集中
- 已结束

开始采集后，只监听用户发起采集时所在的当前 Tab。

---

### 右侧：检测结果

展示本次采集过程中命中的敏感信息。

表格字段：

| 字段 | 说明 |
| --- | --- |
| 时间 | 检测到该数据的时间 |
| 接口 | HTTP Method + 接口地址 |
| 类型 | 命中的规则名称 |
| 敏感信息 | 脱敏后的值 |
| 位置 | JSONPath 或响应中的定位信息 |

示例：

| 时间 | 接口 | 类型 | 敏感信息 | 位置 |
| --- | --- | --- | --- | --- |
| 14:30:25 | GET /api/user/detail | 手机号 | 138****8000 | $.data.user.phone |
| 14:30:21 | POST /api/order/create | 身份证号 | 110105********002X | $.data.idCard |
| 14:30:18 | GET /api/user/info | 完整出生日期 | 1990-**-** | $.data.birthDate |

结果默认按检测时间倒序排列。

---

## 5. 内置规则

### 5.1 中国大陆手机号

目标：检测接口响应中的完整中国大陆手机号。

需要支持常见格式：

```text
13800138000
+86 13800138000
+86-138-0013-8000
138-0013-8000
138 0013 8000
```

以下已脱敏格式不得命中：

```text
138****8000
138****0000
```

结果展示时统一脱敏：

```text
138****8000
```

---

### 5.2 中国居民身份证号

检测：

- 18 位身份证号
- 15 位历史身份证号

18 位身份证必须执行：

- 长度校验
- 出生日期合法性校验
- 校验码验证

示例：

```text
11010519491231002X
```

展示时必须脱敏，例如：

```text
110105********002X
```

---

### 5.3 完整出生日期

检测完整出生年月日，例如：

```text
1990-05-18
1990/05/18
1990.05.18
19900518
1990年05月18日
```

为了降低普通业务日期误报，MVP 仅在具有生日语义的字段中判定出生日期。

生日字段关键词示例：

```text
birthday
birthDate
birth_date
birthDay
birthMonth
dateOfBirth
dob
出生日期
出生年月
生日
```

例如：

```json
{
  "birthday": "1990-05-18"
}
```

需要命中。

而：

```json
{
  "createdAt": "2026-08-21"
}
```

不应命中。

展示时：

```text
1990-**-**
```

---

## 6. 采集范围

MVP 只处理当前 Tab 中的：

- Fetch
- XMLHttpRequest / XHR

采集内容：

- Request URL
- HTTP Method
- HTTP Status
- Response MIME Type
- Response Body

Response Body 只在内存中用于扫描，不长期保存原始正文。

---

## 7. 响应处理

### JSON 响应

优先解析 JSON，并递归扫描所有字段值。

需要记录命中位置，例如：

```text
$.data.user.phone
$.data.list[3].idCard
```

### 非 JSON 响应

对于文本类响应，可直接对正文执行规则扫描。

MVP 不要求支持二进制响应。

---

## 8. 隐私与安全要求

这是本插件的强制要求。

### 8.1 全部本地处理

- Response 不上传服务器
- 敏感信息不上传服务器
- 规则扫描全部在浏览器本地完成

### 8.2 不持久化原始敏感值

扫描结果只允许保存脱敏值，例如：

```text
手机号：138****8000
身份证：110105********002X
生日：1990-**-**
```

禁止把命中的原始值写入：

- localStorage
- IndexedDB
- chrome.storage.local
- chrome.storage.sync
- 日志文件

### 8.3 URL 处理

结果列表中不保存 query string 和 fragment，避免 URL 本身包含敏感参数。

例如：

```text
https://example.com/api/user?idCard=11010519491231002X
```

结果只记录：

```text
https://example.com/api/user
```

---

## 9. 采集状态

### 开始采集

点击后：

1. 绑定当前 Tab
2. 开启 Network 监听
3. 清空上一轮临时网络状态
4. 状态切换为“采集中”

是否清空历史检测结果：

MVP 建议每次点击“开始采集”时自动开启一个新的采集 Session，并清空上一轮展示结果。

### 结束采集

点击后：

1. 停止监听当前 Tab
2. 不再处理新的 Response
3. 保留本轮检测结果供用户查看
4. 状态切换为“已结束”

---

## 10. 规则数据结构

规则引擎需要可扩展，但 MVP 不做复杂 DSL。

建议结构：

```ts
interface ComplianceRule {
  id: string;
  name: string;
  description: string;
  enabled: boolean;
  detect: (
    value: string,
    context: {
      path: string;
    }
  ) => string[];
  mask: (value: string) => string;
}
```

内置规则与未来自定义规则统一走同一个扫描入口。

---

## 11. 检测结果数据结构

```ts
interface Finding {
  id: string;
  detectedAt: number;

  requestId: string;
  method: string;
  url: string;
  status: number;
  mimeType: string;

  ruleId: string;
  ruleName: string;

  path: string;
  maskedValue: string;
}
```

`Finding` 中禁止存在：

```text
rawValue
responseBody
rawResponse
```

等原始敏感数据字段。

---

## 12. UI 交互要求

### 规则列表

- Switch 开启/关闭规则
- 开启后立即用于下一次响应扫描
- 默认启用全部内置规则

### 开始采集

未采集状态可点击。

点击后：

```text
开始采集 → disabled
结束采集 → enabled
```

### 结束采集

采集中可点击。

点击后：

```text
开始采集 → enabled
结束采集 → disabled
```

### 结果列表

- 新结果实时显示
- 默认最新结果在最上面
- 敏感信息必须脱敏
- 没有结果时显示空状态：

```text
暂无敏感信息
```

---

## 13. 异常处理

### 不支持的页面

例如：

```text
chrome://
edge://
chrome-extension://
```

提示：

```text
当前页面不支持采集，请打开普通 HTTP/HTTPS 页面后重试。
```

### Debugger 被断开

如果用户打开 DevTools 或其他原因导致 debugger session 被断开：

- 自动结束当前采集状态
- 页面提示采集已中断
- 用户可重新点击开始采集

### Response 获取失败

单个 Response 获取失败不得导致整个采集过程停止。

只跳过该请求。

---

## 14. 性能要求

MVP 目标：

- 普通页面使用时无明显卡顿
- 单个 Response 扫描不得阻塞 UI
- 对深层 JSON 设置最大递归深度
- 对超大对象设置最大扫描节点数
- 限制单个响应最大扫描体积

当前建议：

```text
最大递归深度：30
最大 JSON 节点：50,000
单 Response 最大扫描体积：10 MB
```

超过限制直接跳过，并可记录非敏感的调试信息。

## 15. MVP 验收标准

### 手机号

接口返回：

```json
{
  "phone": "13800138000"
}
```

结果：必须出现一条手机号检测结果。

显示：

```text
138****8000
```

### 身份证

接口返回合法 18 位身份证：

```json
{
  "idCard": "11010519491231002X"
}
```

结果：必须出现身份证号检测结果。

非法校验码不得命中。

### 出生日期

```json
{
  "birthday": "1990-05-18"
}
```

必须命中。

```json
{
  "createdAt": "2026-08-21"
}
```

不得命中出生日期规则。

### 已脱敏数据

```json
{
  "phone": "138****8000"
}
```

不得产生手机号检测结果。

### 开始/结束

- 点击开始采集后，新接口响应能够被扫描
- 点击结束采集后，新接口响应不得再进入扫描结果

### 数据安全

检查插件存储后：

- 不得存在原始 Response Body
- 不得存在完整手机号
- 不得存在完整身份证号
- 不得存在完整出生日期原值

## 17. MVP 最终形态

用户打开插件后只需要看到三部分：

```text
┌──────────────────────────────┐
│ 规则列表                     │
│ ☑ 手机号                     │
│ ☑ 身份证号                   │
│ ☑ 完整出生日期               │
├──────────────────────────────┤
│ [ 开始采集 ] [ 结束采集 ]    │
├──────────────────────────────┤
│ 敏感信息                     │
│                              │
│ 14:30 GET /api/user/detail   │
│ 手机号 138****8000           │
│ $.data.phone                 │
│                              │
│ 14:31 GET /api/user/profile  │
│ 身份证 110105********002X    │
│ $.data.idCard                │
└──────────────────────────────┘
```

MVP 的设计原则：

> **功能越少越好，打开即用，只做接口明文敏感信息采集与展示。**
