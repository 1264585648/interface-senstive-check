# Interface Sensitive Check — MVP 需求文档

## 1. 产品目标

开发一个纯浏览器插件，用于在用户正常访问网页时，采集当前页面产生的接口响应，并根据预设规则检查返回内容中是否存在不允许明文返回的敏感信息。

MVP 只解决一个问题：

> **接口响应中是否出现了明文敏感数据。命中后必须直接展示接口返回的原始值，便于确认确实发生了明文泄露。**

不判断业务上下文、不判断“是否本人数据”、不做漏洞评级。只要命中启用中的规则，即记录为违规项。

---

## 2. MVP 范围

MVP 仅包含四个核心能力：

1. 维护敏感信息规则列表
2. 开始采集当前页面接口响应
3. 结束采集
4. 展示采集到的敏感信息原文

暂不包含：风险评分、漏洞定级、业务上下文推断、报告中心、统计看板、云端上传、多用户协作、自定义规则编辑等。

---

## 3. 使用流程

```text
打开目标网页
   ↓
打开浏览器插件
   ↓
确认启用的规则
   ↓
点击「开始采集」
   ↓
正常操作网页
   ↓
监听当前 Tab 的 Fetch / XHR 响应
   ↓
响应内容进入本地规则引擎
   ↓
命中规则
   ↓
结果区直接展示命中的敏感信息原文
   ↓
点击「结束采集」
```

---

## 4. 页面结构

整体采用简单双栏布局。

### 4.1 左侧：规则列表

每条规则显示：

- 是否启用
- 规则名称
- 规则说明
- 匹配方式/表达式

MVP 内置三条规则：

| 启用 | 规则名称 | 说明 |
| --- | --- | --- |
| ✓ | 手机号 | 中国大陆完整手机号 |
| ✓ | 身份证号 | 中国居民身份证号 |
| ✓ | 完整出生日期 | 完整年月日 |

MVP 允许启用/停用内置规则。新增、编辑、删除自定义规则放到后续版本。

### 4.2 左侧：采集控制

只保留两个操作：

- **开始采集**
- **结束采集**

状态：未采集、采集中、已结束。

开始采集后，只监听用户点击开始时所在的当前 Tab。

### 4.3 右侧：敏感信息结果

结果表字段：

| 字段 | 说明 |
| --- | --- |
| 时间 | 检测到该数据的时间 |
| 接口 | HTTP Method + 接口地址 |
| 类型 | 命中的规则名称 |
| 敏感信息 | **接口响应中的原始明文值，不脱敏** |
| 位置 | JSONPath 或响应中的定位信息 |

示例：

| 时间 | 接口 | 类型 | 敏感信息 | 位置 |
| --- | --- | --- | --- | --- |
| 14:30:25 | GET /api/user/detail | 手机号 | 13800138000 | $.data.user.phone |
| 14:30:21 | POST /api/order/create | 身份证号 | 11010519491231002X | $.data.idCard |
| 14:30:18 | GET /api/user/info | 完整出生日期 | 1990-05-18 | $.data.birthDate |

结果默认按检测时间倒序排列。

**敏感信息列必须直接展示原文。** 只有看到实际返回的完整值，测试人员才能确认接口确实以明文形式返回了敏感数据。

---

## 5. 内置规则

### 5.1 中国大陆手机号

需要支持常见完整手机号格式：

```text
13800138000
+86 13800138000
+86-138-0013-8000
138-0013-8000
138 0013 8000
```

以下已经脱敏的内容不得命中：

```text
138****8000
138****0000
```

命中后结果区展示接口实际返回的完整原文，例如：

```text
13800138000
```

### 5.2 中国居民身份证号

检测：

- 18 位身份证号
- 15 位历史身份证号

18 位身份证必须执行：

- 长度校验
- 出生日期合法性校验
- 校验码验证

命中后直接展示完整原文，例如：

```text
11010519491231002X
```

### 5.3 完整出生日期

检测完整出生年月日，例如：

```text
1990-05-18
1990/05/18
1990.05.18
19900518
1990年05月18日
```

为了降低普通业务日期误报，MVP 仅在具有生日语义的字段中判定，例如：

```text
birthday
birthDate
birth_date
birthDay
birthMonth
dateOfBirth
dob
出生日期
出生年月
生日
```

例如：

```json
{ "birthday": "1990-05-18" }
```

必须命中；而：

```json
{ "createdAt": "2026-08-21" }
```

不应命中。

命中后直接展示原文，例如 `1990-05-18`。

---

## 6. 采集范围

MVP 只处理当前 Tab 中的：

- Fetch
- XMLHttpRequest / XHR

用于扫描的内容：

- Request URL
- HTTP Method
- HTTP Status
- Response MIME Type
- Response Body

Response Body 只在本地用于扫描，不上传服务器。

---

## 7. 响应处理

### JSON 响应

优先解析 JSON，递归扫描字段值，并记录 JSONPath，例如：

```text
$.data.user.phone
$.data.list[3].idCard
```

### 非 JSON 文本响应

对正文直接执行规则扫描。

MVP 不要求处理二进制响应。

---

## 8. 原文展示与数据安全

### 8.1 全部本地处理

- Response 不上传服务器
- 敏感信息不上传服务器
- 规则扫描全部在浏览器本地完成

### 8.2 命中值必须明文展示

命中规则后，结果表中的“敏感信息”列必须展示接口返回的原始值，不进行掩码或脱敏。

例如：

```text
手机号：13800138000
身份证：11010519491231002X
生日：1990-05-18
```

这是用于确认“接口确实返回了完整明文”的核心证据。

### 8.3 原始值仅允许存在于当前采集会话内存

虽然 UI 必须展示原文，但插件不得把原始敏感值长期持久化。

原始命中值允许存在于：

- 当前 Side Panel 页面运行内存
- 当前采集 Session 的临时内存对象

禁止写入：

- localStorage
- IndexedDB
- chrome.storage.local
- chrome.storage.sync
- chrome.storage.session
- 日志文件
- 远程服务

结束 Session 后当前页面可以继续显示结果；刷新 Side Panel、关闭插件或 Tab 后允许丢失这些原始结果，这是预期行为。

### 8.4 Response Body 不持久化

完整 Response Body 只用于即时扫描，扫描完成后释放，不长期保存。

### 8.5 URL 处理

结果列表不保存 query string 和 fragment，避免 URL 自身携带新的敏感数据。

例如：

```text
https://example.com/api/user?idCard=11010519491231002X
```

结果只展示：

```text
https://example.com/api/user
```

---

## 9. 采集状态

### 开始采集

点击后：

1. 绑定当前 Tab
2. 开启 Network 监听
3. 开启新的采集 Session
4. 清空上一轮页面结果
5. 状态切换为“采集中”

### 结束采集

点击后：

1. 停止监听当前 Tab
2. 不再处理新的 Response
3. 当前页面保留本轮明文结果供用户查看
4. 状态切换为“已结束”

刷新或关闭插件页面后允许清空这些明文结果。

---

## 10. 规则数据结构

```ts
interface ComplianceRule {
  id: string;
  name: string;
  description: string;
  enabled: boolean;
  detect: (
    value: string,
    context: { path: string }
  ) => string[];
}
```

`detect` 返回原始命中值。

---

## 11. 检测结果数据结构

UI 运行时使用：

```ts
interface RuntimeFinding {
  id: string;
  detectedAt: number;
  requestId: string;
  method: string;
  url: string;
  status: number;
  mimeType: string;
  ruleId: string;
  ruleName: string;
  path: string;
  rawValue: string;
}
```

`rawValue` 用于结果表明文展示，但**只允许存在于当前运行内存，不得持久化**。

禁止持久化：

```text
rawValue
responseBody
rawResponse
```

---

## 12. UI 交互要求

### 规则列表

- Switch 开启/关闭规则
- 默认启用全部内置规则
- 规则变化作用于后续响应扫描

### 开始采集

```text
开始采集 → disabled
结束采集 → enabled
```

### 结束采集

```text
开始采集 → enabled
结束采集 → disabled
```

### 结果列表

- 新结果实时显示
- 最新结果显示在最上面
- **敏感信息必须显示原始明文值**
- 不提供默认脱敏模式
- 没有结果时显示“暂无敏感信息”

---

## 13. 异常处理

不支持 `chrome://`、`edge://`、`chrome-extension://` 等页面。

Debugger 被断开时自动结束采集并提示用户；单个 Response 获取失败只跳过该请求，不影响其他请求。

---

## 14. 性能要求

建议限制：

```text
最大递归深度：30
最大 JSON 节点：50,000
单 Response 最大扫描体积：10 MB
```

普通页面使用时不能出现明显卡顿。

---

## 15. MVP 验收标准

### 手机号

接口返回：

```json
{ "phone": "13800138000" }
```

必须命中，UI 必须直接显示 `13800138000`。

### 身份证

接口返回：

```json
{ "idCard": "11010519491231002X" }
```

必须命中，UI 必须直接显示完整身份证号；非法校验码不得命中。

### 出生日期

```json
{ "birthday": "1990-05-18" }
```

必须命中并显示 `1990-05-18`。

```json
{ "createdAt": "2026-08-21" }
```

不得命中出生日期规则。

### 已脱敏数据

```json
{ "phone": "138****8000" }
```

不得产生手机号检测结果。

### 开始/结束

- 开始采集后，新接口响应能够被扫描
- 结束采集后，新接口响应不得进入结果列表

### 数据安全

检查持久化存储后：

- 不得存在原始 Response Body
- 不得存在完整手机号
- 不得存在完整身份证号
- 不得存在完整出生日期原值

但当前打开的结果 UI 中必须能够看到本次 Session 命中的原始值。

## 17. MVP 最终形态

```text
┌────────────────────────────┬──────────────────────────────────────────────┐
│ 规则列表                   │ 敏感信息                                    │
│                            │                                              │
│ ☑ 手机号                   │ 时间     接口        类型     敏感信息       │
│ ☑ 身份证号                 │ 14:30    /api/user   手机号   13800138000    │
│ ☑ 完整出生日期             │ 14:29    /api/info   身份证   110105...002X │
│                            │ 14:28    /api/info   出生日期 1990-05-18     │
│ [开始采集] [结束采集]      │                                              │
└────────────────────────────┴──────────────────────────────────────────────┘
```

核心原则：**规则简单、操作简单、结果明确；命中什么，就把接口实际返回的敏感值原文展示出来。**
